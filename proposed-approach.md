# Proposed approach: AI & Internal Tools Lead (Consultant)

*Draft for [YOUR NAME] to edit. Contains no claims about experience; add those in the CV.*

I would work in short, reviewable steps that match the terms of reference, and I would keep
every decision visible to the people who have to run the tools afterwards.

## Week 1: systems audit and roadmap
Map every tool, spreadsheet and manual process across operations, finance, customer care and
reporting. Interview each team, then score each candidate on value, confidence, effort and risk
with a method I can show you (a ranked workbook plus a keep-or-replace checklist). Critical
systems, meaning site control, metering, billing and the finance books, are flagged and are
never replaced without sign-off from the IT Senior Manager and, for money, the FP&A Lead.
**Output:** a prioritised opportunity list and the cost, time and risk for each item.

## Week 2: architecture proposal
A lean stack chosen with the Cloud Services Manager: hosting, database, authentication and an
integration layer, in Nuru-owned accounts, with MFA, least-privilege access and a secrets
manager from day one. One source of truth for core operational and financial data with access
controls. A clear way to use AI models: approved providers only, no training on Nuru data, no
sensitive data typed into AI tools, and a person reviewing any AI output that affects money.
**Output:** architecture document reviewed by the Cloud Services Manager and IT Senior Manager
before it reaches the CEO.

## Week 4: first priority tool live
The top-ranked tool that passed the checklist, built end to end, run in parallel with the old
way, with a rollback. It goes live only after the IT Senior Manager confirms readiness.
**Output:** the tool, its runbook, monitoring and alerting, a tested backup and restore, and a
walkthrough for the people who will operate it.

## After that: sprints
Fortnightly sprints with the CEO, the Cloud Services Manager and FP&A Lead joining as
relevant, on a shared task tracker. Each tool ships with documentation and a training
session, and its code and deployment configuration sit in a Nuru-owned repository.

## What I would watch
- **Handover:** a tool nobody else can run is a liability, so documentation and training are
  part of "done".
- **Cost:** report running cost and the licence or time it replaces, each tool.
- **Security and data protection:** GDPR principles and DRC law, a data processing
  agreement, incident reporting through Nuru's policy.
- **Scope:** replace only what the audit justifies.
